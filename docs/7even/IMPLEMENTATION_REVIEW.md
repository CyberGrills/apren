## What the project is trying to achieve

7even is a Nigerian hospitality marketplace and operating system for rooms, dining and experiences. A guest can discover a service, hold shared availability, pay through provider checkout, complete the visit, earn points and exchange eligible merchant-funded benefits. Reception, the business dashboard and platform administration read the same records. The core idea retained from Apren is the connection between service value, ownership, exchange and demand; speculative food assets and a cash-like points wallet are not carried forward.

The rebuild makes the important boundaries explicit: the business is the tenant, a venue scopes reception access, a reservation owns an immutable quote, payment success differs from bank settlement, booking rights differ from transferable benefits, and a queued reception update differs from an accepted server update. The selected provider is Flutterwave v3. Commission is 10% of the discounted service before separately stated tax. Actual provider fees reduce the business share.

## What the code now does well

The active system has one PostgreSQL authority, a small pure engine, shared validated contracts, modular backend workflows and five connected React surfaces. Exact amount arithmetic, transaction locks, durable idempotency, balanced append-only journals and visible uncertain outcomes replace the most consequential Apren defects. UI failures and development fixtures are made explicit rather than silently shown as successful activity.

The saved browser review shows a local mock stay progressing through hold, payment, reception fulfillment, once-only points, reward redemption, gift acceptance, authorized benefit consumption and persisted recipient updates. This demonstrates a connected local product journey. It does not demonstrate Flutterwave sandbox processing, real bank settlement, real-world demand accuracy, vendor PMS compatibility, or production deployment.

## Release constraints, not hidden completion claims

Flutterwave is not configured because the user confirmed the account is not ready. Real checkout, split allocation, webhook behavior, refund delivery and bank settlement cannot be certified until a test account and approved merchant subaccounts exist. Keep mock mode local and visibly labelled. A production release also needs qualified financial/auth/tenant review, the required secret/dependency/static/API scan evidence, recovery and reconciliation drills, monitored abnormal-transaction alerts, and applicable Nigerian legal/payment/privacy review.

Login and registration now use PostgreSQL-persisted per-IP and per-email counters shared by workers, alongside recovery limits. Administrators still have no second authentication factor and bank changes have no independent maker-checker control. The local HTTP runtime uses a restricted login inheriting `seven_app`, separate from migration administration. Tenant enforcement remains application-level rather than PostgreSQL row-level security; a compromised broad runtime credential remains consequential. Production proxy/ingress limits and these critical boundaries require qualified review. See the threat model for exact source evidence and residual severity.

The root README and `.env.example` now describe 7even. [Operations](OPERATIONS.md) records startup, role separation, recovery, queue limits and safe rollback. [Architecture](ARCHITECTURE.md) records the five surfaces, financial/tenant boundaries and the deliberate code-and-contract extension path for future sectors. The optional Nodemailer dependency is locked but could not be downloaded during the local session; real SMTP must remain unconfigured until installation and delivery verification succeed. Final-tree command output is recorded separately from older passing runs. The latest npm advisory endpoint request failed; the earlier zero-advisory result was before the added mail dependency and cannot establish the current complete dependency state. Lint exits successfully but reports warnings/information, so it is not described as a clean lint run.
